## Pull Request Description

````markdown
## Summary

This release makes the Scene-DJ sensitive to beat intensity, adds a dedicated CRT shadow-mask shader, and expands the SID emulation test into an audible ADSR/filter sweep laboratory.

- Adds continuous beat strength, shared soft/medium/hard levels, and a decaying strength-weighted beat impulse for DSE rendering.
- Gives the universal Starfield, Copperbars, and TrackPresenter visibly graded responses while preserving exact-event choreography.
- Adds an energy-aware WebGL CRT pass with tube geometry, RGB phosphor structure, scanlines, convergence drift, and a CSS fallback.
- Regenerates `SID_Emulation_Test.sid` with 16-step ADSR and analogue-filter sweeps on a common 220 Hz sawtooth.
- Fixes a full-level SID Attack-retrigger overflow exposed by the new test sequence.
- Updates the curated library to **214 tracks: 73 Amiga, 55 C64, and 86 Atari ST**.

## Changes

### 1. Gradual Scene-DJ beat intensity

`TrackMonitor` now exposes:

- `beatStrength`: continuous strength of the last accepted beat, clamped to `0.0–1.0`.
- `beatLevel`: shared classification into `NONE`, `SOFT`, `MEDIUM`, and `HARD`.
- `beatImpulse[0]`: `beatEnvelope[0] × beatStrength`, providing a smoothly decaying, strength-weighted visual impulse.

The existing exact `beatStarted` and `beatCount` events remain discrete and authoritative. Continuous DSE motion uses `beatImpulse`; pattern, palette, formation, direction, and layout changes still require exact beat events. Retained strength/level values during envelope decay cannot retrigger choreography.

`StageManager` clamps and routes the new metrics and supplies allocation-free compatibility fallbacks for legacy metric objects. The baseline harness adds reproducible soft (`0.20`), medium (`0.50`), and hard (`0.90`) impulses.

### 2. Universal DSE responses

- **Starfield:** grades warp travel and system accents: C64 raster wobble, Amiga nebula/brightness response, and an integer Atari star-size kick. Pattern and palette changes remain exact-beat driven.
- **Copperbars:** grades vertical nudge, climax interference, and core-punch thickness. Formation and Copperlist changes remain restricted to exact fourth beats.
- **TrackPresenter:** grades system-specific panel motion and adds a climax title nudge while preserving one-shot lifetime and exact fourth-beat layout changes.
- **LimitBar:** implements and tests graded isolated responses but intentionally remains disabled in the registry.
- **VoidElement:** remains transparent and does not draw or consume music metrics.

The DSE development rules and audio/visual pipeline documentation now define the intensity contract, fallback behavior, acceptance criteria, and test strengths.

### 3. CRT monitor shadow-mask pipeline

A new `CrtShadowMask` component post-processes the existing demo canvas after visualizer/Scene-DJ and glitch rendering. The fragment shader combines:

- restrained barrel distortion and tube-edge bounds;
- radial red/blue convergence drift;
- five-tap analogue beam-bandwidth smoothing and glass scatter;
- a staggered RGB slot/dot-triad mask with a black matrix and shaped phosphor apertures;
- beam-energy-dependent mask bloom;
- dynamic scanlines that weaken at high brightness;
- phosphor cross-bleed, glass sheen, vignette, and edge shading.

The mask pitch is anchored to CSS pixels. Texture storage is reallocated only when source dimensions change; normal frames reuse it through `texSubImage2D()`. WebGL context loss/restoration is handled explicitly, and the existing CSS scanline presentation remains available when WebGL cannot be used.

### 4. SID ADSR and filter sweep laboratory

The generated PSID v2 test image now contains **60 tests / 4,586 PAL frames / 91.72 seconds**:

1. 40 oscillator patterns.
2. Four 16-step ADSR sweeps: attack, decay, sustain, and release.
3. One dry filter reference.
4. Eleven filter sweeps covering cutoff, resonance, routing, and modes.
5. Four coupling tests.

All ADSR/filter comparisons use the same **220 Hz sawtooth** (`0x21`, frequency word `3746`). ADSR steps retrigger the gate so each setting is audible; release explicitly gates off. Filter steps use a constant full-level envelope and do not retrigger gate or ADSR, isolating the analogue-filter change.

The test is generated as real 6502 code with init/play routines at a 50 Hz PAL call rate. Tests execute that code with the production `CPU6502` and inspect actual SID register writes rather than trusting generator metadata alone.

### 5. SID full-level retrigger fix

A fast gate retrigger could enter Attack while the envelope was already at 255. Incrementing past 255 skipped the former equality-only transition and eventually indexed outside the envelope DAC, producing non-finite output.

Attack now saturates at 255 and enters Decay. The complete test render and regenerated C64 corpus pass without non-finite samples.

## Scope and boundaries

- Gradual-beat rollout in this release covers the universal DSEs; it does not claim a rewrite of every system-specific DSE.
- LimitBar remains disabled. VoidElement remains a transparent placeholder.
- The CRT pass changes final monitor presentation, not the DSE source raster, palette, or music emulation.
- Full CRT shading requires WebGL; unsupported/lost contexts use the CSS fallback.
- SID synthesis remains genuine emulation. The expanded test is a PSID program, not prerecorded audio.
- The displayed duration intentionally truncates 91.72 seconds to `01:31`; this is not a playback-length regression.
- No external framework or runtime service was added.
````
