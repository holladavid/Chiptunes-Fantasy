# Pull Request Title

**fix(mobile): release v1.5.5 with iPhone layout and fullscreen repairs**

# Pull Request Description

## Summary

This hotfix PR prepares Chiptunes Fantasy **v1.5.5**. It repairs four iPhone-specific presentation problems: the permanently visible windowed Now Playing overlay, stage controls beneath the notch, a fullscreen exit button that never auto-hides, and an oversized mobile transport/computer-selection area.

The runtime change is limited to `css/style.css`. No playback, emulation, parser, audio, Scene-DJ, or DSE logic is modified. The **209-track library** and all v1.5.5 features remain unchanged.

## Changes

### 1. Windowed Now Playing auto-hide

- Extends the existing inactivity fade to the windowed Now Playing card.
- Keeps the existing three-second timeout and interaction-based wake-up.
- Prevents **BUS ACTIVE** and track metadata from permanently obscuring the visualization.

### 2. iPhone safe-area handling

- Adds the top safe-area inset before the windowed visualization so the complete stage starts below the iPhone sensor housing.
- Adds horizontal safe-area padding to the mobile application container.
- Keeps the logo and hardware HUD inside safe boundaries in native and pseudo fullscreen.
- Uses stage-scoped safe-area custom properties backed by `env(safe-area-inset-*)` values.

### 3. Fully automatic fullscreen hiding

- Removes the override that forced the fullscreen UI bar and exit button to remain visible after inactivity.
- Allows the entire fullscreen bar to fade and disable pointer events, including **EXIT**.
- Hides the logo alongside the existing Now Playing and collapsed-HUD fades.
- Preserves touch/mouse wake-up and the existing fullscreen exit/focus-restoration flow.

### 4. Compact mobile playback and system controls

- Places all four transport buttons in one row.
- Places timeline and volume controls side by side in a second row.
- Reduces mobile transport padding, gaps, slider heights, and button typography within themed limits.
- Tightens system-tab and core-selector spacing without removing controls.
- Restores explicit flex ratios so transport buttons use the full available row width, including at widths up to 480 px.
- Reduces the measured playback-bar height at 393 px viewport width from **255 px to 95 px**.

### 5. Hotfix documentation

- Updates `README.md` to v1.5.6 with the hotfix scope, behavior, measurements, and validation limits.
- Adds copy-ready GitHub release notes in `doc/releases/v1.5.6-Release-Text.md`.
- Adds this PR description in `doc/releases/v1.5.6-PR-Text.md`.
- Leaves v1.5.5 and earlier release documents unchanged as historical records.

## Scope and boundaries

- No SID, Paula, YM, parser, replay, DSP, AudioWorklet, track-registry, museum, Scene-DJ, or DSE behavior was changed.
- No dependencies, data migrations, track additions, or playlist-path changes are introduced.
- Desktop transport layout is not compacted; the new sizing rules are scoped to mobile breakpoints.
- Compact controls intentionally prioritize visualization and song-library space on small screens.
- The planned historical-feasibility review of individual DSEs is separate follow-up work and is not included here.
- A physical-iPhone acceptance pass is still recommended before public rollout, especially for browser-specific safe-area and fullscreen behavior.

## Validation

### Windowed iPhone-sized viewport

Tested in Chromium with an emulated iPhone 15 viewport at **393 × 659 px**:

- Playback bar height: **255 px before → 95 px after**.
- Windowed Now Playing opacity after inactivity: **0**.
- Transport controls: one row; timeline and volume share the second row.
- System tabs: **36 px** high; core selector: **36 px** high.
- No horizontal document overflow.

### Safe-area and Lab Mode

Using a simulated **47 px top inset**:

- Visualization top: **47 px**.
- Logo top: **65 px**.
- Hardware HUD top: **57 px**.
- Lab Mode control top: **66 px** after interaction.
- Lab Mode opened successfully with `aria-expanded="true"` and a visible HUD body.

### iOS-style pseudo-fullscreen

- Fullscreen fallback occupied the complete 393 × 659 px viewport.
- After inactivity, the fullscreen UI bar, Now Playing card, logo, and collapsed HUD reached **zero opacity**.
- The fullscreen bar and logo disabled pointer interaction; the exit button was hidden with its parent bar.
- Stage interaction restored the controls.
- **EXIT** returned the visualization to `demo-container` and restored windowed mode.

### Narrow-screen layouts

At **320 × 568 px**, C64, Amiga, and Atari control configurations showed no horizontal document overflow. The four transport buttons retained their compact single-row layout.

### Test limitations

- These checks used headless Chromium viewport emulation and a simulated safe-area value, not a physical iPhone or WebKit on iOS.
- The full automated test suite was not rerun because the runtime patch is CSS-only; no claim of a newly green full suite is made.
- The known v1.5.5 limitations and pre-existing SID synthetic-corpus mismatch remain disclosed and unchanged in scope.
