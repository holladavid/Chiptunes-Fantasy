# 💾 Chiptunes Fantasy v1.5.8

### Feel the Beat. Hear the Chip. See the Tube.

Version 1.5.8 gives the Scene-DJ a sense of **beat strength**, puts a sophisticated **CRT shadow-mask shader** in front of the demo canvas, and turns the SID test suite into a hands-on **ADSR and analogue-filter listening laboratory**.

The library now contains **214 directly playable tracks**:

- **73 Amiga**
- **55 C64**
- **86 Atari ST**

As always: genuine SID, Paula, and YM emulation — no MP3s and no prerecorded chip-audio shortcuts.

## ✨ Highlights

### 📺 A real CRT finish, not just a scanline overlay

The new WebGL post-processing pipeline gives the existing demo canvas a coherent vintage-monitor presentation:

- restrained barrel distortion and tube-edge shading;
- radial red/blue convergence drift;
- analogue beam-bandwidth smoothing;
- a staggered RGB slot/dot-triad shadow mask with black matrix;
- phosphor apertures whose mask bloom follows beam energy;
- dynamic scanlines that recede at high brightness;
- phosphor cross-bleed, glass sheen, and vignette.

The mask keeps a stable CSS-pixel pitch while the underlying C64, Atari, and Amiga effects retain their own low-resolution, system-correct raster. Texture storage is reused between frames, and WebGL context loss/restoration is handled. If WebGL is unavailable, the existing CSS scanline presentation remains available.

### 🥁 Beats now have weight

The Scene-DJ no longer treats every accepted beat as the same full-strength hit. Each beat now carries:

- a continuous strength from **0.0 to 1.0**;
- a shared **soft / medium / hard** level;
- a smoothly decaying, strength-weighted visual impulse.

Universal DSEs use that impulse for visible intensity while exact beat events still control choreography. In other words: a soft beat can gently nudge the scene, a hard beat can punch it — without accidentally changing the pattern twice while the envelope fades.

| DSE | What now reacts to beat strength |
| --- | --- |
| **Starfield** | Warp thrust, C64 raster wobble, Amiga nebula/brightness accents, and Atari star-size kick |
| **Copperbars** | Vertical nudge, climax interference, and core-punch thickness |
| **TrackPresenter** | System-specific panel movement and climax title nudge |
| **LimitBar** | Graded isolated responses; still intentionally disabled in the registry |
| **VoidElement** | Deliberately nothing — it remains a transparent placeholder |

Pattern, palette, formation, direction, and layout changes remain locked to exact beat events. The DSE baseline harness includes reproducible soft, medium, and hard impulses for before/after comparisons.

### 🎹 SID envelopes and filters you can actually compare

`SID_Emulation_Test.sid` is now a **60-test, 91.72-second** generated 6502 program.

After 40 oscillator patterns, a common **220 Hz sawtooth** becomes the reference tone for:

1. **Attack:** 16 steps from slow to fast.
2. **Decay:** 16 steps from slow to fast.
3. **Sustain:** 16 steps from low to high.
4. **Release:** 16 steps from slow to fast, with an explicit gate-off.
5. **Analogue filter:** a dry reference followed by 11 cutoff, resonance, routing, and mode sweeps.
6. **Coupling:** four final combined tests.

Every ADSR/filter step uses the same base tone. ADSR sweeps retrigger the gate so each setting speaks clearly. Filter sweeps hold the envelope at constant full level and leave gate/ADSR untouched between steps, so the filter itself is what you hear.

The new sequence also exposed a real emulation edge case: a fast retrigger at full Attack level could overflow the 8-bit envelope counter. Attack now saturates at 255 and enters Decay correctly. The full test render completes with zero non-finite samples.

## 🎧 Suggested listening and visual checks

1. Load **SID Emulation Test Suite** on C64 and listen through the oscillator patterns into the four ADSR sweeps.
2. Compare the common sawtooth across attack, decay, sustain, and release; then listen to the dry filter reference and the following filter-only sweeps.
3. Watch Starfield, Copperbars, and TrackPresenter through quiet and loud passages. Soft and hard beats should differ in amplitude without causing extra pattern or layout changes.
4. Resize the player and enter fullscreen. The CRT mask should keep its CSS-pixel pitch rather than scaling into a blurry texture.
5. If possible, test with WebGL disabled and simulate context loss. The player should remain usable through its CSS fallback and recover when the context returns.

## ✅ Validation

- **62/62 focused release-feature tests passed** across CRT rendering/fallback, graded Scene-DJ/DSE behavior, SID register sequencing, envelope saturation, and C64 curation.
- The complete **4,586-frame / 91.72-second** SID Exact-engine render produced **zero non-finite samples**.
- Full-test measured RMS was approximately **0.119626**, with a peak of approximately **0.474824**.
- Browser playback completed; the UI correctly showed **01:31**, its intentional whole-second truncation of 91.72 seconds.
- The regenerated C64 corpus passed **55/55 tracks** for audible, finite, deterministic, block-size-independent, and restart-identical playback.

The full regression run reported **427 tests: 411 passed, 9 failed, 7 skipped**. The remaining failures are the known unrelated SID synthetic-corpus `noise-adsr` hash mismatch and eight FFT/oscilloscope tests. The focused release suite is green; the complete suite is not represented as all green.

## Scope and known limitations

- The gradual-beat rollout covers universal DSEs; it is not a claim that every system-specific DSE has been rewritten.
- LimitBar remains disabled. VoidElement remains transparent.
- Full CRT shading requires WebGL. Appearance and performance can vary by GPU/browser; physical-device acceptance is still recommended.
- Existing C64/SID random-access seeking limitations remain outside this release.
- The known unrelated full-suite failures listed above remain visible rather than being hidden by the release notes.

## Run or upgrade

1. Download the `v1.5.8` source archive or check out the tag.
2. Serve the project directory over HTTP:

   ```bash
   npm start
   ```

3. Open the printed local URL in a modern browser. No framework build step is required.
4. For audio worklets and module loading, use the HTTP server rather than opening `index.html` through `file://`.

To replace an existing installation, use the `v1.5.8` files and retain only your own deliberately separate local modifications. No audio assets need to be generated or downloaded separately.
