# Pull Request Title

**feat: release v1.5.4 with Amiga Exact and 48 curated classics**

# Pull Request Description

## Summary

This release PR completes Chiptunes Fantasy v1.5.4 across all three sound-chip pillars. It delivers the bounded six-stage Amiga Exact refinement program, expands the Amiga and C64 libraries by 24 classics each, stabilizes C64 environmental diagnostics, and fixes Atari YM5 Digidrum starts without changing global YM6 behavior.

The music disk grows to **205 directly playable tracks**: **69 Amiga**, **50 C64**, and **86 Atari ST** titles. Existing Amiga and C64 playlist entries remain in place. Museum research now distinguishes historical context, facts from the supplied local binary, and source provenance; public archive availability is not treated as a license grant.

## Changes

### 1. Amiga Exact — phases 0–5

#### Measurement and corpus evidence

- Adds a real-production-worklet offline harness with separate `paula`, `zoh`, and `a500` taps, deterministic reports, optional PCM16 WAV output, and restart/block-size comparisons.
- Inventories the real playlist by file hash, format, channels, duration, effects, patterns, samples, and COSO/HIP structures.
- Resolves required fixtures recursively and fails on missing or ambiguous required files rather than silently skipping integration coverage.
- Keeps historical phase reports and their provenance intact; self-generated hashes are treated as regression anchors, not hardware truth.

#### Paula state, reset, and pause/resume

- Makes `AUDxVOL = 0` silence only the DAC while active DMA, periods, byte phase, pointers, and loop state continue.
- Resets all channel, DMA, replay, sequencer, tracker-effect, filter, FIR, and visualization state on `PLAY_TRACK`.
- Makes COSO/HIPC, HIP68K, MOD, and XM restarts bit-identical to fresh worklets, including format changes.
- Separates pause from restart: `STOP_TRACK` freezes output and state, while resume continues without losing DMA, sample, effect, replay, or filter history.

#### COSO/HIPC and HIP68K timing

- Centralizes PAL timing in `js/worklets/lib/amiga-timing.js` and uses CIA timer period 14188, producing a replay tick of approximately 49.99852 Hz.
- Applies the same timing source to production replay, comparison renderers, and UADE-analysis tooling.
- Schedules HIP68K DMA starts and loop LC/LEN writes at their documented raster-derived offsets, preserving initial-versus-loop register order.
- Keeps the claim bounded: this is targeted replay/raster scheduling, not complete cycle-accurate 68000 bus emulation.

#### MOD/XM semantics

- Advances arpeggio, portamento, tone-portamento, vibrato, tremolo, volume slides, and combined effects beyond tick zero, with effect memory where required.
- Adds linear XM frequency conversion, sample offset, XM panning, global volume, and coverage for variable pattern lengths and multi-channel attenuation.
- Tests synthetic effect cells and renders the real MOD/XM corpus through the production worklet.
- Does not claim a complete FastTracker II instrument/envelope engine.

#### A500 output approximation and production integration

- Removes uncalibrated LF347/`tanh` and additional `tanh` saturation from Exact.
- Retains the declared linear 4.421 kHz RC filter, optional 3.09 kHz LED filter, 255-tap FIR, and 0.7 output scale.
- Advances LED-filter history continuously during bypass so re-enabling does not reuse stale state.
- Aligns registry and telemetry wording with the actual linear, four-times-host-rate implementation.
- Adds production acceptance for representative sample rates, long renders, heap stability, real Chromium AudioWorklet integration, Master DSP, UI controls, and desktop/mobile viewports.

### 4. Stable C64 environmental diagnostics

- Excludes the fourth C64 telemetry slot—the SID bus-rate value—from channel-level averaging.
- Removes `Math.random()` jitter from environmental readouts.
- Replaces frame-rate-dependent smoothing with elapsed-time-based smoothing.
- Contains invalid telemetry and verifies reset behavior and plausible responses to level/temperature changes.
- Changes only the presentation/sensor model, not SID emulation or replay.

### 5. Atari YM5 Digidrum normalization

- Normalizes YM5 frames in `js/parsers/ym-parser.js` before shared effect decoding; global YM6 behavior remains unchanged.
- Maps YM5 R3 bits 4–5 to Digidrum starts on voices A/B/C and leaves R1 untouched because it belongs to YM5 Timer Synth.
- Adds a real *Punish Your Machine* frame-2307 regression proving that normalized R3 `0x31` starts sample 0 on voice C.
- Audits 20 sample-based tracks: eight affected YM5 tracks are fixed, eleven YM6 tracks remain correctly decoded, and *Turrican 1* has sample blocks but no Digidrum start commands.

## Scope and boundaries

- No MP3 or prerecorded-audio playback was introduced.
- Existing Amiga and C64 playlist entries were retained; the 26 existing C64 SID binaries were not replaced.
- No historical music-file rights are newly granted. Modland/HVSC availability is not public domain or a general redistribution/commercial-use license.
- C64 environmental changes do not retune SID synthesis; the Atari YM5 normalization does not alter global YM6 decoding.
- Amiga RC/LED filters remain software approximations, not measured mainboard calibration. No new hardware/UADE reference-WAV acceptance is claimed.
- Amiga MOD/XM replay is not presented as a complete FastTracker II instrument engine.
- Atari Exact remains a fixed-2-MHz register-dump player, not full MC68000/MFP/SNDH or Atari-STE DMA emulation.
- C64/SID random-access seeking remains unavailable.
- Self-generated hashes are regression anchors, not hardware truth references. No failing SID baseline was overwritten.
- Offline measurements and headless Chromium viewports do not establish physical-device listening quality, latency, or underrun freedom.
